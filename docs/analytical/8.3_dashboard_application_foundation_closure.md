## 2. Objective

Establish the first executable client-facing dashboard application foundation using the technology decision established in Milestone 8.0 and the evidence boundaries established through Milestones 8.1 and 8.2.

The implementation is intentionally evidence-bounded. It provides dataset-specific descriptive exploration without inventing final business KPIs, unsupported cross-dataset relationships, or unavailable machine-learning outputs.

## 7. Runtime Warning Cleanup

The initial application execution exposed two compatibility warnings:

1. deprecated Pandas categorical-type detection;
2. deprecated Streamlit `use_container_width` usage.

The application was then updated to:

* use `isinstance(dtype, pd.CategoricalDtype)` for categorical detection;
* use `width="stretch"` for Streamlit dataframes and charts.

The final application launch completed without either warning.

## 9. Data Protection

The application does not modify:

* `data/cleaned`

---

## 10. Cross-Dataset Join Boundary

The dashboard application currently treats each analytical dataset independently.

Dataset selection does not imply permission to combine datasets.

Cross-dataset analytics remain blocked until a separate evidence-backed contract establishes:

* relationship path;
* join direction;
* cardinality;
* grain compatibility;
* duplicate behavior;
* fan-out behavior;
* null/orphan handling;
* aggregation strategy;
* reconciliation against source data;
* final metric semantics.

This prevents unsupported measure inflation and uncontrolled many-to-one or one-to-many aggregation.
