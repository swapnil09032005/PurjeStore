## 14. Decisions

- 4.0.3-B locks one source file and one grain key per candidate.
- Source scope is locked to the latest validated cleaned source directory, not to raw data or the live database.
- Raw source files remain protected and are used only for counterpart existence/count checks.
- `accounts` and `offer_usage_tracking` use controlled source-native ID fallback keys because prior candidate grain fields were incomplete over the full row population.
- Relationship/fan-out controls are carried forward; they are not resolved by joining data in this milestone.
- No KPI, ML target, dashboard metric, or business-impact claim is approved by this milestone.

## 15. Limitations and Deferred Work

- 4.0.3-B does not validate join paths or fan-out outcomes. That belongs to 4.0.3-C.
- 4.0.3-B does not construct approved analytical datasets. That belongs to a later controlled construction milestone.
- Candidates marked `RELATIONSHIP_REVIEW_REQUIRED` or `DEFERRED_PENDING_EVIDENCE` remain subject to downstream join/source review before construction.
- Source-native fallback keys are structural locks, not business-grain interpretations.
