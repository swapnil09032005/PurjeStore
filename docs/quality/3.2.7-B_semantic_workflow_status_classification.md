## Objective

This task converts the workflow/status candidate fields discovered during 3.2.7-A into evidence-based semantic classifications.

The purpose is to determine the semantic role of each candidate before any workflow consistency or transition rule is created.

A field is not considered a confirmed workflow/status field solely because its name contains words such as `status`, `state`, `approval`, `review`, or `workflow`.

Classification considers both:

- column-name semantics;
- observed value patterns;
- normalized value distributions;
- controlled workflow/status vocabulary;
- identifier/code signals;
- free-text signals;
- error/result semantics;
- reason-field semantics;
- ambiguity requiring human review.

## Important methodological distinction

This task performs **semantic classification**, not workflow anomaly detection.

For example, identifying an `orderStatus` field does not establish which transitions are valid.

Similarly, observing values such as `pending`, `completed`, or `cancelled` does not establish a universal transition rule.

Workflow consistency must be evaluated using:

- the actual business context;
- related workflow fields;
- relevant timestamps;
- entity relationships;
- repeated records where applicable;
- documented lifecycle semantics when available.

Therefore, this task does not label individual workflow values or transitions as invalid.
