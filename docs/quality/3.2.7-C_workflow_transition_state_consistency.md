## 6. Investigation Methods

### 6.1 Observed State Profiling

Observed workflow/status values were normalized only for comparison.

Normalization included:

- trimming surrounding whitespace
- converting text to lowercase
- collapsing repeated whitespace

Raw source values were not changed.

### 6.2 Multi-Status State Combinations

Tables containing multiple workflow/status fields were examined for observed
combinations.

A combination is evidence of an observed state pattern only.

It is not automatically considered valid or invalid.

### 6.3 Temporal Transition Observation

Potential datetime fields were identified conservatively.

Datetime parseability was checked before temporal ordering.

Where an identifier-like entity key and parseable timestamp were available,
state observations were ordered by timestamp.

The resulting transitions represent observed data behavior.

They do not establish intended business rules.

### 6.4 Structural Conflict Detection

The investigation searched for the following strong structural signal:

- same entity
- same timestamp
- multiple distinct workflow states

Such records are classified as structural conflict signals requiring
semantic investigation.

They are not automatically confirmed business anomalies.

## 8. Interpretation Policy

Evidence is classified using the following hierarchy:

1. Observed pattern
2. Structural conflict signal
3. Requires semantic investigation
4. Confirmed anomaly only after sufficient supporting evidence
5. Insufficient evidence where a definitive conclusion is not justified

This prevents unsupported business rules from entering the data-quality
assessment.
